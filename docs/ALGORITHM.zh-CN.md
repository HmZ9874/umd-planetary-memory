# UMD 行星记忆算法白皮书（中文）

## 1. 研究目标

UMD 的目标不是把整段历史永久塞进提示词，而是建立一个可写入、可更新、可遗忘、可授权、可恢复且可审计的长期记忆系统。它必须同时处理：

- 哪句话值得记忆；
- 同一事实的新旧版本；
- 主题、事件、人物、时间和因果关系；
- 多用户、租户、权限与加密；
- 小 RAM 工作集与磁盘归档；
- 单事实首位检索与大证据集合完整回忆；
- 直接事实、跨会话推理和三跳以上图推理；
- 噪声、提示注入、记忆投毒和错误长期演化。

## 2. 宇宙层级

| 宇宙概念 | 记忆概念 |
|---|---|
| 宇宙 | 租户/用户的完整长期记忆空间 |
| 星系 | 项目、领域或长期身份空间 |
| 恒星 | 稳定主题、人物或任务 |
| 行星 | 事件、事实、偏好、程序经验 |
| 卫星 | 局部细节、来源、相邻证据 |
| 小行星带 | 低质量、弱相关或候选证据 |
| 引力边 | 语义、实体、时间、因果、从属关系 |
| 反物质 | 删除、取消、失效和否定事实 |
| 事件视界 | 有限上下文预算下的压缩边界 |
| 引力弹弓 | 通过中间实体进行多跳推理 |

该比喻不是界面装饰；每个概念都对应有界的数据结构、排序项或状态转换。

## 3. 写入与原子化

输入首先被分解为不可变来源和若干原子事实。确定性本地规则负责信任、证据跨度、字段上限、时间合法性和注入风险；可选 LLM 只能提出实体、关系和时间，不能绕过写入门控。

写入概率由显式重要度、可信度、新颖度、未来效用、重复度和风险共同决定。被拒绝写入的文本仍可保留在调用方日志，但不会进入稳定记忆。

每条事实至少包含：

`(subject, predicate, object, valid_time, knowledge_time, source_id, tenant, state)`

来源文本不可变；更新创建新版本边，旧事实转为 superseded，而不是被静默覆盖。

## 4. 状态机与遗忘

主要状态为 provisional、stable、superseded、tombstone 和 archived。

1. 新事实进入 provisional；
2. 重复验证、明确确认或高可信来源提高质量与质量质量（mass）；
3. 冲突事实按有效时间、知识时间、来源权威和更新序号形成版本链；
4. 删除/取消形成 tombstone 或负状态质量；
5. 不活跃低效用节点迁移到磁盘归档；
6. 审计轨道保留历史，当前答案轨道排除失效事实。

遗忘不是简单删除向量，而是同时更新答案状态、审计状态、关系边、索引、事务日志和加密持久化。

## 5. 分层检索

查询依次经过：

1. BM25 词法共振；
2. 字符 n-gram 容错共振；
3. 神经向量相似度；
4. 星系/会话/主题层级质量；
5. 实体和值共振；
6. 时间相位；
7. 相邻与关系图通量；
8. 状态质量、权限和反物质排斥；
9. 事件卫星覆盖与胶囊压缩；
10. 必要时启动三跳引力弹弓。

候选神经嵌入采用惰性计算；只有词法场选出的有限候选需要向量常驻。历史元数据、密文事实与事务日志可以完全留在持久层，RAM 只保留活动工作集和小型索引。

## 6. 胶囊与完整证据回忆

普通 top-k 把一个位置绑定到一个来源，难以同时满足 R@1 和完整证据集合回忆。UMD 将一个检索位置定义为 provenance-preserving capsule：

`C_k = (anchor, adjacent evidence, relation satellites, echo sources)`

十个稳定锚点不可被新优化删除。新增证据采用条带方式分布到十个胶囊，因此旧 top-k 来源集合始终是新集合的子集。这给出了前缀回忆单调性：

`Sources_old(@k) ⊆ Sources_new(@k)`

严格原子轨道同时公开，每个位置只含一个不可变来源，用于防止通过扩大胶囊宽度虚增 R@1。

## 7. 当前状态、历史与反物质

当前问题和历史问题使用不同状态场。当前问题降低删除、完成、取消事实的答案质量；历史问题保持正负版本中性，以便重建变化过程。

结构化失效事件被压缩成不可变反物质来源 ID 集合，由 answer、atomic、striped 和 state-sector 四个通道共享。这样既保留审计历史，又避免每次查询多次扫描完整文本。

## 8. 大集合 census

集合、统计、推荐和“列出所有”问题不应只检索最相似的十条。UMD 的 census 轨道：

- 从问题检测集合广度和聚合意图；
- 使用全局词元/领域接触和状态过滤排序；
- 对 current、superseded、tombstone 分轨；
- 生成紧凑结构化 payload；
- 对计数、求和、时间窗和维度聚合执行确定性求解；
- 每个结果保留事实级 provenance。

## 9. UMD 3.30 三跳引力弹弓

### 9.1 激活条件

只有当文本包含足够密集的编号主体—关系—客体事实时才构图。普通 LoCoMo 对话、自然段和用户聊天不会激活该路径。

### 9.2 版本化边

编号事实被解析为：

`e = (subject, relation, object, ordinal, source_ids)`

对可见前缀 `t`，同一 `(subject, relation)` 只让序号最大的边产生当前引力；历史边仍可审计。

### 9.3 有界搜索

问题中最长匹配主体成为发射恒星。系统根据问题词语确定目标关系，例如 continent、official_language、head_state、works_field。广度优先搜索最多三跳，路径能量由关系接触和终点势能组成。

如果路径为：

`Phoenix Inferno → sport → basketball → created_country → Italy → head_state → Sergio Mattarella`

则最终答案事实来源被提升到原子首位，而不是停留在第一跳的球队事实。

### 9.4 回声卫星

图推理得到的对象是模型预测，不是 benchmark 标准答案。系统查找该对象在可见记忆中的其他出现位置，形成最多 96 个回声卫星。它们只追加到胶囊，不删除旧锚点，因此提升 Full Recall 的同时保持前缀保护。

## 9.5 UMD 3.31 输出槽证据闭包

3.30 的主要失败并非缺少图，而是把问题中最长的关系线索误当成最终输出。例如“某人的配偶在哪里去世”可能停在 `married`，而不是继续到 `died_city`。3.31 用显式输出槽规则产生终点关系质量 `Ω(r|q)`，再执行最多四跳的闭包搜索。

命中终点后，系统形成三层闭包：答案事实 `Primary`、系统预测对象的全部可见回声 `Echo`、路径中间边的来源 `Dependency`。严格通道按 `Primary → Echo → Dependency → 原 3.30 顺序` 去重排列，且每个名次仍只含一个来源，不用加宽排名单位制造 Full Recall。

该路径仍只在密集编号事实宇宙中激活；在本地 LoCoMo 10 段完整会话扫描中，3.30 与 3.31 均为 0/10 激活。

## 9.6 UMD 3.32.1 关系叠加与版本影子

3.32.1 不再把终点关系解析成单一标签，而是叠加答案头、输出槽和显式关系线索；五跳搜索允许必要的隐含中间边带有小幅负“真空能”，终点质量、关系覆盖率和多路径共识共同决定答案对象。对于相同版本序号的碎片边，系统确定性优先选择更完整的对象和来源集合。

当前答案仍先进入 `Primary → Echo`；同一主语—关系的历史版本随后进入 `Shadow`，最后加入路径依赖。这样可以同时回答现状与演变问题，而不让旧事实挤到首位。Final 闭包最多携带 256 个卫星来源；Strict 始终每名次一个来源，并把普通胶囊按列展开以提升大集合完整召回。容量变化与排序变化在报告中分开披露。

稀有实体词法桥和 MS MARCO cross-encoder 都在本地消融中降低 R@1，因此没有进入默认算法。关系叠加图仍只在密集编号事实宇宙中激活；普通 LoCoMo 对话保持冻结路径。

## 9.7 UMD 3.33.1 双文档恒星与终点吸收

3.33.1 在规则固定窗口上无损重建 `Document N:` 文档边界，把完整文档作为恒星、交叠窗口作为来源卫星。Final 首胶囊保留旧来源并追加前两颗恒星的卫星；Strict 仍每名次一个来源，只有文档首位相对次位达到 `1.13×` 才提升其内部最强来源。

结构化图在覆盖全部查询支持终点后立即吸收，拒绝实体回环，并对重复关系减 `1.25` 能量。这修复了直接事实命中后继续沿 `citizen → head_government → citizen` 游走的错误。普通对话、非规则窗口和不足 20 个文档边界的上下文自动关闭文档恒星。

## 9.8 UMD 3.34 查询裂变与用户陈述核

完整问题保持为中央恒星；含谓词的真实子句最多形成四个子场，短名词并列保持完整。第一人称记忆问题最多增加一个确定性声明式改写。中央问题、子句和用户核词法轨道以轮转方式形成最多 96 来源的有界发现视界。

角色对话同时保留用户陈述核和完整审计文本。Strict 首位主要由用户核施加引力，避免助手长篇推荐仅因重复主题而吸走问题；完整来源仍可检索和审计。首位变化要求 `1.08` 分数比、`0.055` 边际和用户词汇接触门。普通非角色文档不能直接激活这一首位修复。

对复合问题，每个子场最多提供一个卫星进入守恒 Final 首胶囊与覆盖轨道；旧首胶囊来源不会被删除。

## 9.9 UMD 3.35 后台幽灵物质

幽灵是随活动索引生成的可丢弃导航痕迹。它只蒸馏角色化对话中的用户事实子句；请求、助手扩写和没有正事实质量的文本不会生成可检索内容。绝对日期相对当前可见前缀的最大日期投影为“几天前、上周几、上个月”等别名，因此不会借用未来会话。

幽灵只有在偏好或时间问题上唤醒，普通文档和直接事实题保持原路径。蒸馏文本永远不能成为证据，命中必须回锚到原始 `source_id`。Final 首胶囊可以守恒追加两个原始来源；Strict 则完全复用 3.34 胶囊矩阵，只有明确时间计算/排序问题通过词法接触 `0.35`、分数比 `1.055` 和边际 `0.035` 三重门时才允许提升原始来源。助手输出回忆和简单相对日期筛选被排除。

## 9.10 UMD 3.36 有界幽灵星座

3.36 根据查询模式估计证据多重性，并在两个以上事实与问题产生至少 `0.05` 词法接触时激活版本共振。幽灵语义轨道与 Strict 原子轨道形成双轨共识，分别最多贡献 12 和 6 个候选。

所有迁移来源必须已存在于迁移前 Final@10 来源并集；首胶囊只执行集合追加，Strict 则从迁移前快照计算。因此 Final@10 来源/字符预算与所有 Strict 名次保持不变。该机制优化证据打包，不扩大检索视界。

## 10. 持久化、安全与多租户

UMD 3.6+ 提供：

- SQLite 持久化与有界 RAM 活动集；
- AES-256-GCM 租户密文；
- HMAC 链式事务日志；
- 原子提交、回滚和重启恢复；
- 租户隔离、ACL/ABAC 与 capability token；
- 密钥轮换和错误密钥拒绝；
- 编码器身份校验，防止用不同向量模型错误恢复索引。

主密钥必须由外部 KMS/HSM 或 secret manager 管理，不能和数据库放在一起。

## 12. 已知限制

- 公开成绩主要是来源检索代理，不等于回答正确率；
- MemoryAgentBench 尚未计分 Test-Time Learning 和 Long-Range Understanding；
- 对非模板化开放图推理，当前确定性关系解析器覆盖有限；
- 回声对象过于常见时仍需容量上限，避免上下文膨胀；
- 尚无七天以上真实用户故障率、成本和质量漂移报告；
- 算法尚未经过同行评审，也没有官方 leaderboard 认证。
