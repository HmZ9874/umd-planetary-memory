# UMD 3.29 性能优化报告

日期：2026-08-11

## 结论

UMD 3.29 是一次检索语义不变的性能升级。它不读取答案、证据标签或题目类别，也不修改 UMD 3.28.2 的力学权重、候选预算或排序规则。

- 286 块真实 MemoryAgentBench 上下文的带剖析冷查询：7.818 秒降至 2.316 秒，约 3.37 倍加速，耗时下降 70.4%。
- 2,307 块上下文：建库 3.175 秒；冷查询 2.801 秒；后续九问平均 0.972 秒；十问合计 11.547 秒。
- 反物质缓存阶段使 2,307 块十问从 14.325 秒进一步降至 11.547 秒，下降 19.4%。
- 69 项适配器与性能回归全部通过。
- 星座覆盖公式 200 组随机对抗等价检查通过；指令引力公式 200 组随机对抗等价检查通过。

## 新的执行定律

### 1. 增量星座覆盖场

设第 `t` 轮已经覆盖的词元集合为 `C_t`，候选记忆 `i` 的词元集合为 `T_i`，重叠质量为：

`o_i(t) = |T_i ∩ C_t|`

原公式中的新增信息与冗余项保持不变：

`novel_i(t) = (|T_i| - o_i(t)) / max(1, |T_i|)`

`redundancy_i(t) = o_i(t) / max(1, |T_i| + |C_t| - o_i(t))`

选中记忆 `j` 后，只对新进入覆盖场的词元更新倒排表：

`o_i(t+1) = o_i(t) + Σ[x ∈ T_i], x ∈ (T_j - C_t)`

这与旧集合交并公式严格等价，但避免在每轮为所有候选复制大集合。

### 2. 查询不变量引力场

问题模式、历史查询信号、多证据查询信号和问题词元只计算一次。每个记忆仍使用原 UMD 3.14 指令引力公式；相对引力排序与瞬态桥共享同一个结果向量。

### 3. 反物质状态压缩

显式删除、取消和遗忘事件在建库阶段压缩为不可变来源 ID 集合。答案、原子答案、条带答案和状态扇区答案共享该集合，避免每问四次扫描完整文本。

### 4. 溯源成员场

结构化事实溯源先构造一次 provenance 集合，再进行常数时间成员判断，修复了在每条事实上重复构造集合的问题。

## 内存影响

星座倒排表是单次查询的临时结构，候选上限仍为 192，查询结束后释放。词元复用现有 3.25 census token 场，没有新增全库词元副本。持久新增状态仅是反物质来源 ID 的小型 `frozenset`，因此没有引入稠密图或全量神经向量常驻 RAM。

## 边界

本轮验证的是排序公式等价、性能和回归稳定性，并未重跑所有耗时很长的官方端到端基准。因此旧的 UMD 3.28.2 检索分数仍是当前正式质量分数；UMD 3.29 暂不宣称新的 LoCoMo、LongMemEval 或 MemoryAgentBench 正式分数。
